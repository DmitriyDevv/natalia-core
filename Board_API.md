# Board_API

`Board_API` — единственный аппаратный контракт, видимый уровню `Algorithm`.
Объявления: `BSP/Board_API/include/board_api.h`.

Уровень `Algorithm` (автомат состояний, действия, transport, MRAM-store) обращается
к аппаратуре **только** через эти функции и не знает о регистрах, GPIO, шинах,
DMA, IRQ и внутренностях драйверов. Если алгоритму нужен аппаратный факт или
операция, которых нет в `board_api.h`, добавляется новая функция Board_API, а не
обход уровня.

## Общие правила

- Почти все функции возвращают `BoardStatus` (`Core/include/status.h`):

  | Значение                | Смысл                                  |
  | ----------------------- | -------------------------------------- |
  | `BOARD_OK`              | Успех.                                 |
  | `BOARD_ERR_INVALID_ARG` | Неверный аргумент (NULL, размер, id).  |
  | `BOARD_ERR_TIMEOUT`     | Таймаут операции.                      |
  | `BOARD_ERR_IO`          | Ошибка ввода-вывода / шины.            |
  | `BOARD_ERR_CRC`         | Несовпадение CRC.                      |
  | `BOARD_ERR_BUSY`        | Ресурс занят.                          |
  | `BOARD_ERR_NOT_READY`   | Устройство/данные не готовы.           |
  | `BOARD_ERR_UNSUPPORTED` | Функция не поддерживается в этой сборке.|

- Три функции связи возвращают `void` (`board_comm_close`, `board_comm_poll`,
  `board_comm_get_status`) — отмечено в их описании.
- В таблицах параметров столбец «Напр.» — направление: **вход** (аргумент читается)
  или **выход** (по указателю функция записывает результат).
- API детерминированный и пригоден для хостовых тестов: при
  `NATALIA_USE_BOARD_STUBS=ON` те же функции реализованы заглушками
  (`Algorithm/src/board_api_stub.c`); при отключённом драйвере реальная сборка
  возвращает предсказуемый статус (обычно `BOARD_ERR_UNSUPPORTED`).
  Заглушка моделирует не всё: часть функций отдаёт константы. Полный разбор —
  в разделе «Поведение хостовой заглушки» ниже. Читайте его перед тем, как
  писать хостовый тест: иначе легко принять константу заглушки за проверенное
  поведение.
- Board_API **не** содержит логики автомата, не знает переходов режимов, не
  вызывает `handle_event()` и не кладёт события в очередь.
- Длительные операции неблокирующие: запуск + опрос завершения (см. NAND).
- `copy_id` (копия MRAM), `bank_id` / `nand_bank` (банк NAND) — значения `1` и `2`.
- Аппаратные события отдаются алгоритму счётчиками через `*_take_*_events()`:
  вызов возвращает число накопленных событий и обнуляет внутренний счётчик.

## Типы данных

### Перечисления

```c
typedef enum { BOARD_SIGNAL_NAND1 = 0, BOARD_SIGNAL_NAND2, BOARD_SIGNAL_PED, BOARD_SIGNAL_RTC_OUT } BoardSignalTarget;
typedef enum { BOARD_POWER_MONITOR_PU = 0, BOARD_POWER_MONITOR_PED } BoardPowerMonitorId;
typedef enum { BOARD_TEMP_SENSOR_PU = 0, BOARD_TEMP_SENSOR_PED } BoardTempSensorId;
```

### `InstrumentTime` (`Core/include/instrument_time.h`)

| Поле           | Тип        | Единицы            |
| -------------- | ---------- | ------------------ |
| `seconds`      | `uint32_t` | секунды            |
| `milliseconds` | `uint16_t` | миллисекунды       |

## MRAM (конфигурация и служебные данные)

Две горячо-резервируемые копии (`copy_id` = 1/2).

#### `board_mram_read(uint8_t copy_id, uint32_t offset, void* buffer, size_t size)`

Чтение из копии MRAM.

| Параметр  | Тип        | Напр. | Описание                          |
| --------- | ---------- | ----- | --------------------------------- |
| `copy_id` | `uint8_t`  | вход  | Копия MRAM (1 или 2).             |
| `offset`  | `uint32_t` | вход  | Смещение внутри копии, байт.      |
| `buffer`  | `void*`    | выход | Буфер приёмника.                  |
| `size`    | `size_t`   | вход  | Число читаемых байт.              |

#### `board_mram_write(uint8_t copy_id, uint32_t offset, const void* buffer, size_t size)`

Запись в копию MRAM. CRC образа пересчитывается реализацией.

| Параметр  | Тип           | Напр. | Описание                       |
| --------- | ------------- | ----- | ------------------------------ |
| `copy_id` | `uint8_t`     | вход  | Копия MRAM (1 или 2).          |
| `offset`  | `uint32_t`    | вход  | Смещение внутри копии, байт.   |
| `buffer`  | `const void*` | вход  | Источник данных.               |
| `size`    | `size_t`      | вход  | Число записываемых байт.       |

#### `board_mram_check_crc(uint8_t copy_id, uint8_t* is_valid)`

Проверка CRC копии.

| Параметр   | Тип        | Напр. | Описание                         |
| ---------- | ---------- | ----- | -------------------------------- |
| `copy_id`  | `uint8_t`  | вход  | Копия MRAM (1 или 2).            |
| `is_valid` | `uint8_t*` | выход | 1 — CRC верна, 0 — нет.          |

#### `board_mram_restore_copy(uint8_t source_copy_id, uint8_t target_copy_id)`

Восстановить одну копию из другой.

| Параметр          | Тип       | Напр. | Описание                  |
| ----------------- | --------- | ----- | ------------------------- |
| `source_copy_id`  | `uint8_t` | вход  | Копия-источник (1 или 2). |
| `target_copy_id`  | `uint8_t` | вход  | Копия-приёмник (1 или 2). |

#### `board_mram_write_test_result(uint8_t copy_id, uint8_t nand_bank, const void* data, size_t size)`

Запись результатов теста ППЗУ (`Nerr`) для банка.

| Параметр    | Тип           | Напр. | Описание                                          |
| ----------- | ------------- | ----- | ------------------------------------------------- |
| `copy_id`   | `uint8_t`     | вход  | Копия MRAM (1 или 2).                             |
| `nand_bank` | `uint8_t`     | вход  | Банк NAND (1 или 2).                              |
| `data`      | `const void*` | вход  | Данные результатов, `BOARD_MRAM_TEST_RESULT_SIZE`.|
| `size`      | `size_t`      | вход  | Размер данных (`6144`).                           |

#### `board_mram_read_test_result(uint8_t copy_id, uint8_t nand_bank, void* data, size_t size, uint8_t* is_valid, uint8_t* crc_out)`

Чтение результатов теста. `crc_out` отдаёт сохранённые байты CRC образа (может быть `NULL`).

| Параметр    | Тип        | Напр. | Описание                                          |
| ----------- | ---------- | ----- | ------------------------------------------------- |
| `copy_id`   | `uint8_t`  | вход  | Копия MRAM (1 или 2).                             |
| `nand_bank` | `uint8_t`  | вход  | Банк NAND (1 или 2).                              |
| `data`      | `void*`    | выход | Буфер результатов, `6144` байт.                   |
| `size`      | `size_t`   | вход  | Размер буфера (`6144`).                           |
| `is_valid`  | `uint8_t*` | выход | 1 — образ валиден.                                |
| `crc_out`   | `uint8_t*` | выход | 2 байта сохранённой CRC; `NULL` — не нужен.       |

## Шаблоны использования (длительные операции)

Все длительные операции кооперативные: запуск, затем опрос завершения по одному
ограниченному шагу за вызов главного цикла. Ниже — псевдокод порядка вызовов
(упрощён, обработка ошибок опущена). Реальные последовательности — в поллерах
`Algorithm/src/algorithm.c` и `Algorithm/src/actions.c`.

### Стирание банка NAND (ERASE, финальное стирание TEST)

```c
board_nand_erase_start(bank);                 // запуск, не блокирует
// каждый шаг главного цикла:
board_nand_erase_is_done(bank, &is_done);     // опрос
// когда is_done == 1 -> поставить в очередь EVENT_ERASE_DONE / перейти к следующей стадии
```

### Пакетная запись НИ в NAND (TEST-запись, накопление OBSERVE)

```c
board_nand_open_write(bank, start_packet_count); // открыть сессию записи
// на каждый пакет (2048 байт):
board_nand_write_packet(bank, packet);           // поставить пакет
// продвигать неблокирующе, по шагу за цикл:
board_nand_write_flush(bank, &is_done);          // is_done == 1 -> пакет записан
// board_nand_write_poll(bank, &is_idle) — продвинуть очередь; is_idle == 1, когда пуста
```

### Пакетное чтение NAND (DUMP, чтение-сверка TEST)

```c
board_nand_open_read(bank, packet_count);              // packet_count — верхняя граница
// по индексу:
board_nand_read_packet(bank, packet_index, buffer);    // buffer — 2048 байт
// либо потоком:
board_nand_read_next_packet(bank, buffer, &has_packet);// has_packet == 0 -> данные кончились
```

### Вывод пакета по USB (DUMP)

```c
board_usb_is_ready(&is_ready);                         // при подготовке интерфейса
// отправка пакета по частям, по шагу за цикл:
board_usb_write(&buffer[offset], remaining, &bytes_written);
// offset += bytes_written; при ошибке/0 — повтор (ограниченное число раз)
board_usb_write(NULL, 0U, &bytes_written);             // финальный флаш при завершении
```

### Обмен по связи (главный цикл / transport)

```c
board_comm_poll(now_ms);                               // продвинуть RX/TX и таймауты
while (board_comm_receive(&message, buffer, capacity) == BOARD_OK) {
    // разобрать и обработать принятое сообщение
}
board_comm_send(&message);                             // поставить ТС на передачу
board_comm_get_status(&status);                        // при необходимости — состояние канала
```

### Сбор аппаратных событий (предусмотрено для OBSERVE; ещё не подключено)

```c
board_rtc_take_1hz_events(&count);                     // забрать секундные тики (1 Гц)
board_ped_take_trigger_events(&count);                 // забрать триггеры ПЭД
// счётчик обнуляется; алгоритм ставит соответствующие события в очередь
```

## Поведение хостовой заглушки

`Algorithm/src/board_api_stub.c`, флаг `NATALIA_USE_BOARD_STUBS=ON`. Реализует
все функции этого документа, поэтому уровень `Algorithm` собирается и работает
на обычном ПК без кросс-компилятора и без платы.

Заглушка **детерминированная**: одинаковые вызовы всегда дают одинаковый
результат, случайных отказов и задержек нет. Проверка аргументов (NULL, номер
копии/банка, выход за границу) выполняется по-настоящему и возвращает
`BOARD_ERR_INVALID_ARG` — это единственный класс ошибок, который заглушка
порождает сама.

### Параметры модели

| Параметр | Значение в заглушке | На плате |
| --- | ---: | ---: |
| Банков NAND | 2 | 2 |
| Ёмкость банка, пакетов | **64** | 262144 |
| Размер пакета, байт | 2048 | 2048 |
| Копий MRAM | 2 | 2 |
| Размер копии, байт | 1024 | 1024 (`BOARD_MRAM_COPY_SIZE`) |

Область конфигурации совпадает с полётной, различаются только NAND: ёмкость
банка в заглушке меньше почти в 4000 раз.

Ёмкость банка задана `BOARD_STUB_NAND_PACKET_COUNT`. Разница с полётной почти
в 4000 раз — режим TEST, который работает блоками по 128 пакетов, на хосте
выполняет ноль блоков.

Инициализация выполняется один раз за процесс (`board_stub_init_once`): NAND
заполняется `0xFF`, MRAM — нулями. **Функции полного сброса нет**, поэтому
внутри одного тестового бинарника состояние NAND и MRAM переносится из теста в
тест.

### Система

| Функция | Поведение |
| --- | --- |
| `board_init_hardware` | Инициализирует модель, `BOARD_OK`. |
| `board_enter_safe_config` | `BOARD_OK`, ничего не делает. |
| `board_disconnect_signal_lines` | `BOARD_OK`, ничего не делает. |

| Функция | Поведение |

| `board_mram_restore_copy` | Настоящее копирование копии в копию. |
| `board_mram_write_test_result` / `board_mram_read_test_result` | Настоящие, отдельная область на банк и копию. |

| Функция | Значение |

| Функция | Поведение |

### Связь

Настоящая модель на **один слот** приёма и **один слот** передачи.

| Функция | Поведение |
| --- | --- |
| `board_comm_init` | Сбрасывает слоты, `BOARD_OK`. |
| `board_comm_close` / `board_comm_poll` | Ничего не делают. |
| `board_comm_send` | Сохраняет сообщение в слот передачи, увеличивает счётчик. |
| `board_comm_receive` | Отдаёт ожидающее сообщение и снимает признак; если его нет — `BOARD_ERR_NOT_READY`. |
| `board_comm_get_status` | `is_online = true`, `tx_busy = false`, `tx_messages_failed = 0`. |

Управление из теста (`Algorithm/include/board_comm_stub.h`):

```c
void     board_comm_stub_reset(void);
void     board_comm_stub_inject_rx(uint16_t message_id, uint16_t address_from,
                                   uint16_t address_to, const uint8_t* data,
                                   uint16_t length);
uint32_t board_comm_stub_tx_count(void);
bool     board_comm_stub_last_tx(uint16_t* message_id, uint16_t* address_to,
                                 uint8_t* buffer, uint16_t capacity,
                                 uint16_t* length);
```

Оба слота одиночные: второй `inject_rx` до вызова `transport_poll()` затирает
первый, а `board_comm_stub_last_tx()` отдаёт только последнее переданное
сообщение. Чтобы проверить несколько ответов подряд, разбирайте их по шагам,
сверяясь с `board_comm_stub_tx_count()`.

### Сводка ограничений

Через хостовую заглушку **нельзя** проверить: обработку неверной CRC в MRAM,
таймауты и отказы NAND, отказ подтверждения питания, отказы и повторы вывода
данных, ход времени, секундные тики RTC, триггеры ПЭД, выход параметров за
пороги. Для этого нужна либо доработка заглушки, либо стендовая проверка
(`tests/firmware/`).

## Реализации

Одна и та же сигнатура имеет две реализации; при изменении API нужно править обе:

- `BSP/Board_API/src/board_api.c` — реальная прошивочная реализация (за
  соответствующими флагами `NATALIA_ENABLE_*_DRIVER`; при отключённом драйвере —
  детерминированная заглушка / RAM-фолбэк);
- `Algorithm/src/board_api_stub.c` — хостовая заглушка для тестов
  (`NATALIA_USE_BOARD_STUBS=ON`), описана выше.

Использование Board_API уровнем `Algorithm` — в [`Algorithm.md`](Algorithm.md).
